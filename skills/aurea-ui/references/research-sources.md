# UI/UX Research Source Map

Use this reference to select sources deliberately. These sources are starting points, not a universal checklist. For a current-trend scan, use the live web and verify each selected source because URLs, ownership, feeds, and product offerings can change.

## Source-selection rule

Choose sources based on the design question:

1. Product evidence and the existing design system come first.
2. Use official standards and mature design systems for system mechanics and accessibility.
3. Use research organizations for evidence-backed usability questions.
4. Use real-product libraries for flow and pattern research.
5. Use curated galleries for visual exploration and art direction.
6. Use detail libraries for motion and delight.

Never treat a visual gallery as usability evidence.

## Standards and mature design systems

### W3C Web Content Accessibility Guidelines (WCAG 2.2)
URL: https://www.w3.org/TR/WCAG22/
Use for: accessibility requirements, perceivable/operable/understandable/robust criteria, focus, reflow, contrast, target size, and related conformance guidance.
Role: normative accessibility source.

### Material Design 3
URL: https://m3.material.io/
Use for: tokenized systems, components, adaptive layouts, color, type, motion, and platform-scale system thinking.
Caution: learn the system logic; do not make every web product look like a Google product.

### Apple Human Interface Guidelines
URL: https://developer.apple.com/design/human-interface-guidelines/
Use for: platform behavior, hierarchy, interaction, accessibility, input, motion, and Apple-platform conventions.
Caution: apply platform-specific guidance only where the target platform warrants it.

### Microsoft Fluent 2
URL: https://fluent2.microsoft.design/
Use for: design principles, web/product component behavior, tokens, content, accessibility, and motion systems.

### Adobe Spectrum
URL: https://spectrum.adobe.com/
Use for: scalable design-system principles, semantic design tokens, components, complex creative-product UI, and system governance.

### IBM Design Language and Carbon Design System
URLs:
- https://www.ibm.com/design/language/
- https://carbondesignsystem.com/
Use for: enterprise product design, data-heavy UI, content, accessibility, system principles, component architecture, and disciplined visual language.

### Shopify Polaris
URL: https://polaris-react.shopify.com/
Use for: admin-product information architecture, merchant workflows, foundations, content, and system thinking. A useful reminder from Polaris is to treat the design system as a floor rather than a ceiling: components support product decisions, they do not replace them.

### Atlassian Design System
URL: https://atlassian.design/
Use for: SaaS/product foundations, tokens, spacing, grids, typography, elevation, forms, navigation, content, and dense collaborative-product UI.

### GOV.UK Design System
URL: https://design-system.service.gov.uk/
Use for: task-first services, forms, content clarity, accessibility, focus states, mobile-first layout, and evidence-driven simplicity.

### U.S. Web Design System (USWDS)
URL: https://designsystem.digital.gov/
Use for: accessible, trustworthy, mobile-friendly public-service design, principles, tokens, components, and maturity models.

## Usability and research

### Nielsen Norman Group
URL: https://www.nngroup.com/
Use for: usability heuristics, information architecture, interaction patterns, research methods, forms, navigation, and broad UX evaluation.
Caution: heuristics are diagnostic principles, not rigid layout laws.

### Baymard Institute
URL: https://baymard.com/research
Use for: research-backed ecommerce UX, product finding, cart, checkout, forms, mobile commerce, and benchmarks.
Caution: ecommerce findings are strongest in ecommerce context; do not generalize them blindly to unrelated products.

## Real-product flows and UI patterns

### Page Flows
URL: https://pageflows.com/
Use for: onboarding, signup, checkout, upgrade, search, settings, dashboards, modals, navigation, and end-to-end flow behavior.
Best for: understanding sequence and state changes rather than copying isolated screens.

### Mobbin
URL: https://mobbin.com/
Use for: real mobile and web product screens, patterns, and multi-screen flows from shipped products.
Best for: product UI conventions and comparison across apps.

### UI.live
URL: https://ui.live/components
Use for: current creator-shared components and interface ideas across buttons, cards, navigation, forms, dashboards, dark mode, and related categories; inspect its Trending and Explore views when available.
Best for: a quick component-level visual pulse and implementation vocabulary.
Caution: community examples are inspiration, not evidence of accessibility, responsive quality, or production readiness.

### Refero
URL: https://refero.design/
Use for: curated real-product UI references, patterns, elements, and design research.
Best for: targeted product-interface reference work.

### Nicelydone
URL: https://nicelydone.club/
Use for: web-app flows and patterns from established products.
Best for: SaaS/product flow research.

### SaaSFrame
URL: https://www.saasframe.io/
Use for: SaaS marketing pages, product interfaces, emails, pricing, onboarding, and common SaaS patterns.
Best for: SaaS-specific comparison.

### SaaS UI pattern libraries
Example: https://www.saasui.design/
Use for: pattern-level comparisons across real SaaS products.
Caution: verify the underlying examples rather than treating the aggregator's interpretation as ground truth.

## Visual and art-direction inspiration

### Awwwards
URL: https://www.awwwards.com/
Use for: ambitious art direction, typography, storytelling, motion, unusual composition, WebGL/3D, and experimental interaction.
Caution: many entries optimize for showcase impact. Do not import experimental navigation or heavy effects into task-heavy products without justification.

### Land-book
URL: https://land-book.com/
Use for: contemporary full-site composition, landing pages, portfolios, product marketing, typography, and section rhythm.

### SiteInspire
URL: https://www.siteinspire.com/
Use for: curated website art direction, typography, editorial layouts, grids, minimalism, portfolios, ecommerce, and category-specific visual research.

### One Page Love
URL: https://onepagelove.com/
Use for: one-page narrative, hero-to-CTA structure, section ordering, social proof, pricing, FAQ, and landing-page rhythm.

### Dribbble
URL: https://dribbble.com/
Use for: broad visual exploration, composition, color, illustration, typography, dashboards, and concept discovery.
Caution: isolated shots are not proof of responsive behavior, complete state coverage, or usable flows.

### Recent
URL: https://recent.design/
Use for: current curated design, websites, digital products, app screenshots, icons, motion, and 3D inspiration.
Best for: a contemporary visual pulse across more than website galleries alone.
Freshness note: Recent states that it took the place of the discontinued Godly gallery in 2026. Verify this relationship and the current feed before citing it.
Caution: use editorial selection as visual vocabulary, not product-UX evidence.

### Dark Design
URL: https://www.dark.design/
Use for: handpicked dark-themed websites, current dark-mode art direction, typography, surface treatment, contrast strategy, imagery, and atmospheric motion.
Best for: dark landing pages and brands whose identity genuinely calls for a dark presentation.
Caution: a dark aesthetic is not automatically premium or accessible. Verify contrast, readability, focus, media treatment, and light-environment usability.

## Detail, motion, and delight

### Design Spells
URL: https://www.designspells.com/
Use for: microinteractions, small details, delightful transitions, playful states, easter eggs, and memorable product moments.
Best for: finding one or two meaningful signature moments after the core UX is sound.

## Fresh trend scan source recipe

When [design-research.md](design-research.md) requires a current-trend scan:

1. Start with live comparable products or a real-product library such as Mobbin or Page Flows for shipped behavior.
2. Inspect at least one current broad visual feed such as Recent, Awwwards, Land-book, or SiteInspire. Use New, Recent, Trending, or Popular views when the source provides them.
3. Add a focused source only when it matches the question: UI.live for component-level ideas, Dark Design for a genuinely dark direction, Design Spells for detail and delight, or official technical showcases for motion and 3D feasibility.
4. Verify the source is active and the referenced work is recent enough for the claim being made. Record the access date for material influences.
5. Separate recurring visual signals from product evidence. Words such as "trending," "popular," and "award-winning" describe editorial or community attention, not usability or conversion quality.

Use the current date in searches when it improves precision, but do not restrict the scan to pages whose titles contain a year. Recently published work and currently shipped products matter more than SEO labels such as "best websites 2026."

## How to combine sources

### Task-heavy SaaS or admin product
Start with: existing product -> Page Flows/Mobbin/Refero -> mature design systems -> NN/g -> visual galleries only for refinement.

### Ecommerce
Start with: product evidence -> Baymard -> Page Flows/Mobbin -> relevant design system -> visual references.

### Marketing landing page
Start with: content strategy -> comparable shipped products -> Recent/Land-book/SiteInspire -> Awwwards for ambitious art direction -> UI.live or Design Spells for focused details -> Dark Design only for a justified dark direction -> design-system constraints.

### Creative portfolio/editorial site
Start with: brand/content -> Recent/SiteInspire/Land-book/Awwwards -> relevant interaction details -> accessibility/performance validation.

### Mobile product flow
Start with: target-platform conventions -> Mobbin/Page Flows -> Apple HIG or relevant platform guidance -> local design system.

## Research quality rules

- Search for the product archetype and task, not only the visual style.
- Prefer several references with distinct roles over one reference to imitate.
- Record why each reference is useful.
- Verify current product behavior when freshness matters.
- Distinguish official standards, research findings, real-product examples, and subjective inspiration.
- Never cite popularity as evidence that a pattern is usable.
- Never copy proprietary branding, artwork, or distinctive page composition wholesale.
